# Stockholm source assessment

Checked: **2026-10-12** · Candidate: `se-stockholm` / `prorelsehindrad-all` (not registered) · [Issue #822](https://github.com/NIPKaart/disabled-parking/issues/822)

**Decision: do not connect Stockholm with the current package and delivery contract.** The official source remains a plausible candidate and permits reuse, but current retrieval completeness and identity have not been verified. The package lacks the shared collection interface and loses source context; its historical fixture contains geometry that core rejects. This is a technical hold, not a finding that Stockholm's data is unavailable or unsuitable forever.

| Topic | Conclusion | Mapping / handling | Evidence |
| --- | --- | --- | --- |
| Source and selection | The official parking API documents `prorelsehindrad/all` for parking reserved for disabled permit holders. These are interpreted local traffic regulations, not an inventory of independently verified physical bays. | Review this municipal selection; do not substitute Stockholm Parkering's facility API or infer individual bays from facility counts. | [Official API guide](https://openparking.stockholm.se/home/Parking), [datasets](https://openparking.stockholm.se/home/Data) |
| Reuse | Trafikkontoret states that service data may be freely reused and supplied licence-free unless otherwise stated. No verified SPDX licence is identified here. | A future source block should preserve the official terms and publisher attribution, with `licence: null`; do not assign CC0 or copy the package's MIT licence onto the data. | [Publisher reuse statement](https://openstreetws.stockholm.se/home/) |
| Authentication | The service requires an API key. No `STOCKHOLM_API_KEY` was configured in the inspected collector environment. A read-only request without a key to `prorelsehindrad/all?outputFormat=json` returned HTTP 200 and zero body bytes. | An empty body is a retrieval failure, not a complete empty dataset. Configure a legitimate key locally; never put it in a source URL, delivery or committed fixture. | [Key registration](https://openparking.stockholm.se/Home/Key), direct unauthenticated request on the check date |
| Identity | The historical package fixture has feature `id`, `FID`, `FEATURE_OBJECT_ID` and `FEATURE_VERSION_ID`. The model keeps only `FID` as `location_id`. Live uniqueness and continuity have not been established. | Verify the identifier semantics and full-selection uniqueness before choosing `external_id`. Preserve all original identity/version fields; do not synthesize an ID from an address or coordinates. | [Pinned model](https://github.com/klaasnicolaas/python-odp-stockholm/blob/279855ea778a5c9b72ea42f632bbdb7f42cd468c/src/odp_stockholm/models.py), [historical fixture](https://github.com/klaasnicolaas/python-odp-stockholm/blob/279855ea778a5c9b72ea42f632bbdb7f42cd468c/tests/fixtures/disabled_parking.json) |
| Geometry | All five historical fixture features are WGS84 LineStrings. The package keeps coordinates but drops the geometry type. Current core accepts only Point, Polygon and MultiPolygon. Live geometry distribution remains unknown. | Preserve original geometry. Do not disguise a line as a Point or invent a polygon. Verify live types; if lines remain, agree and test a core contract extension and marker derivation before connecting. | [Historical fixture](https://github.com/klaasnicolaas/python-odp-stockholm/blob/279855ea778a5c9b72ea42f632bbdb7f42cd468c/tests/fixtures/disabled_parking.json), [core validator](https://github.com/NIPKaart/core/blob/a6ed5773c913e141a11d72969d425b8e6d3a34ba/app/Support/MunicipalSnapshot.php), [authoritative geometry contract](https://github.com/NIPKaart/core/blob/main/docs/development/data-import-contract.md) |
| Completeness | The client requests `maxFeatures=limit` (default 10) and returns only parsed features. It does not validate `numberMatched`, `numberReturned`, duplicates, limits or versions. The 2023 fixture reports 2,045 matches and five returned features; this is not today's count. | Add a public `parking_collection` interface in the package, preserving raw fields and complete geometry. Prove full retrieval against source counts, validate unique IDs and the safety ceiling, and fail without a partial collection on inconsistencies. | [Pinned client](https://github.com/klaasnicolaas/python-odp-stockholm/blob/279855ea778a5c9b72ea42f632bbdb7f42cd468c/src/odp_stockholm/odp_stockholm.py), [historical fixture](https://github.com/klaasnicolaas/python-odp-stockholm/blob/279855ea778a5c9b72ea42f632bbdb7f42cd468c/tests/fixtures/disabled_parking.json) |
| Access, capacity and currency | The selection establishes permit-holder parking. Per-record personal reservation, the meaning of `EXTENT_NO`, and current coverage are not verified. `VALID_FROM`/`VALID_TO` describe validity, not maintenance time; response `timeStamp` is not a surveyed-at date. | Keep unverified access/capacity unknown, retain validity and rule fields in `source_attributes`, and leave `source_updated_at` unknown without a documented modification field. Check the treatment of expired/future regulations before mapping. | [Official selection](https://openparking.stockholm.se/home/Parking), [historical source fields](https://github.com/klaasnicolaas/python-odp-stockholm/blob/279855ea778a5c9b72ea42f632bbdb7f42cd468c/tests/fixtures/disabled_parking.json) |
| Administrative identity | SCB lists municipality Stockholm as `0180` in Stockholms län. Core has no Swedish municipality scheme yet. | Preserve the leading zero; add and test a Swedish SCB scheme tied to country `SE` only when connecting the source. Verify the ISO subdivision and operational bounds alongside live geometry. | [Official SCB codes](https://www.scb.se/hitta-statistik/regional-statistik-och-kartor/regionala-indelningar/lan-och-kommuner/lan-och-kommuner-i-kodnummerordning/), [core source validator](https://github.com/NIPKaart/core/blob/a6ed5773c913e141a11d72969d425b8e6d3a34ba/app/Support/SourceDescription.php) |

## Conditions for implementation

1. Configure a legitimate API key and collect current evidence: complete count, IDs, geometry types, coordinate system, validity selection, raw attributes and source limits. Treat historical fixtures as examples only.
2. Release the package collection interface with malformed-response, authentication, count, duplicate, ceiling and geometry tests. Requests and completeness checks belong in the package, not a second HTTP client in this collector.
3. Add Swedish area validation in core and, if required by live geometry, explicitly supported line geometry with preservation and PostGIS marker derivation. Test invalid geometry and area identities as well as discovery, approval and intake.
4. Add the small collector mapping and dataset/source registration using uv and the existing `nipkaart-municipal-2` exporter, scheduler, pending-state and private R2 transport. Test preservation and rejection of incomplete, duplicate, invalid and out-of-bounds collections, including retention of the last valid delivery.
5. Demonstrate a real complete export/delivery and isolated core discovery, source approval, first intake and repeat intake. Record exact revisions and results. Production activation remains [core #1303](https://github.com/NIPKaart/core/issues/1303).

Legacy [PR #416](https://github.com/NIPKaart/disabled-parking/pull/416) only adds credentials and a Poetry dependency; it cannot provide the required delivery. Replace that proposal with this assessment and the subsequent implementation once the gates above are satisfied. Keep [#822](https://github.com/NIPKaart/disabled-parking/issues/822) open while live verification and integration remain outstanding; do not reopen [#412](https://github.com/NIPKaart/disabled-parking/issues/412).
